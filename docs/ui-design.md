# UI / UX 設計文件

**版本：** 2026-04-18 初稿
**目標：** 把三個 Mode 的畫面、流程、元件規格寫下來，讓後續實作有藍圖
可循。本文以 wireframe + 互動描述為主，**不鎖死視覺風格**（顏色、字型、
動畫由設計師或後續迭代決定）。

本文適讀對象：工程師實作、PM 對齊需求、以及之後可能加入的設計師。

---

## 1. 設計原則

這三個原則會被拿來當決策依據，有衝突時依序：

1. **行動載具優先。** 使用者 100% 用手機直式（portrait）瀏覽，不設計
   桌機版。所有互動都是單手拇指可觸及。
2. **相機優先於 UI。** Mode A 的主畫面是鏡頭畫面——任何 UI 都是疊在
   上面的薄薄一層，不遮擋作品。
3. **零摩擦進入。** 從掃 QR 到看到 AR 最多三次點擊（開啟 → 授權相機 →
   對準 QR）。不要求註冊、不強迫登入、不留 e-mail。

## 2. 通用元件

三個 Mode 共用的元件。放在 `apps/web/src/components/` 的 shadcn/ui 基礎上。

### 2.1 Top Status Bar

```
┌─────────────────────────────────────┐
│ ◀ Back    tcsh-web-ar         ⋮    │
└─────────────────────────────────────┘
```

- 高度 48px，半透明深色背景（rgba(0,0,0,0.5)），讓相機畫面透出來。
- 左：返回鍵（Mode A 回模式選擇；Mode B/C 回上一頁）。
- 中：當前 Mode 的名稱或狀態（「Station A」、「3D Viewer」等）。
- 右：overflow menu（切換 Mode、語言、關於）。

### 2.2 Bottom Toast（訊息提示）

```
     ┌───────────────────────────────┐
     │ ⓘ  請對準地面上的 QR code      │
     └───────────────────────────────┘
```

- 從底部浮出，停留 3 秒自動消失。
- 三種類型：`info`（藍）、`warning`（黃）、`error`（紅）。
- Mode A 的 tracking 狀態訊息都用這個呈現。

### 2.3 Loading Overlay

```
┌─────────────────────────────────────┐
│                                     │
│              ◌ 載入中                │
│           正在下載貼圖...             │
│                                     │
└─────────────────────────────────────┘
```

- 全螢幕半透明黑色遮罩 + 旋轉 spinner + 描述文字。
- 用在 Mode B 載 glTF、Mode C 上傳中。

### 2.4 Permission Modal

```
┌─────────────────────────────────────┐
│                                     │
│    📷 需要相機權限                    │
│                                     │
│    這個作品需要透過鏡頭才能看到 AR      │
│    疊加的貼圖，我們不會儲存任何影像。    │
│                                     │
│    [ 允許使用相機 ]                   │
│                                     │
└─────────────────────────────────────┘
```

- iOS 特別要求：motion sensor 權限要使用者**主動點擊**才能請求
  （`DeviceOrientationEvent.requestPermission()`）。這個 modal 是那個
  觸發入口。
- 一併請求 camera + motion 權限，一次要完。

## 3. Mode A — 現場 AR 體驗

最複雜、最高風險、也最核心的 mode。從使用者角度的完整 flow：

```
                                              ↓
                                         [物件詳情]
                                              ↓
                                      [移動到下一站]
```

- 這是「離散觀賞站」UX 的關鍵引導畫面——沒有它，使用者不知道接下來
  要去哪。
- 跳過按鈕讓自由探索的使用者可以回 A2 選擇任一站點。

### 3.8 Error / Edge States

- **Camera 權限被拒：** 全螢幕 error，教使用者怎麼在 iOS 設定裡開回，
  加上 fallback 連結到 Mode B。
- **Motion 權限被拒：** warning toast，但仍允許使用——IMU 沒了會讓
  AR 體驗很差，UI 提示「建議開啟方位感測器才能獲得完整體驗」。
- **偵測不到 QR 超過 30 秒：** 全螢幕 modal「需要協助嗎？」提供「查看
  QR 位置圖」或「回模式選擇」。
- **Wi-Fi 斷線：** 貼圖 lazy load 失敗時用 low-res placeholder，並
  retry。

- 變更是**本地暫存**（React state），點「儲存變更」才 PATCH 到 API。

### 5.6 Screen C6 — 預覽

Studio 裡直接內嵌 Mode A / Mode B 的 iframe（或同 route 切換），讓創作
者不用拿手機測試小改動。

## 6. 視覺語言（暫定，之後由設計師接手）

這些是**暫行 default**，等有設計師進場可以全換：

- **主色：** 純黑 `#000` + 純白 `#FFF`（呼應作品「單色」語彙）。
- **強調色：** `#00E5FF`（科技感青，用在 QR 偵測框、active station）。
- **錯誤色：** `#FF5252`
- **警告色：** `#FFAB00`
- **成功色：** `#00C853`
- **字型：** 系統字（iOS 用 -apple-system，Android 用 Roboto）。中文
  用 Noto Sans TC。
- **Radius：** 按鈕 8px，卡片 12px，Drawer 16px（頂部）。
- **陰影：** 只用一層大陰影（shadcn/ui 預設）做浮層。

## 7. 實作順序建議

按「可獨立驗證」排序：

1. **Mode A 的 A3（QR 掃描）+ A4（AR 觀賞）** — 這是技術上最難的部分，
   先把 happy path 跑通。
2. **Mode B 的 B1 + B2** — glTF 載入與基本 OrbitControls。風險低，可
   平行做。
3. **Mode A 的 A2（站點選擇）+ A6（跨站引導）** — 等 A4 基本 work 之後。
4. **Mode C 的 C1 + C2** — 登入與 Dashboard 骨架。
5. **Mode C 的 C3 + C4** — 貼圖庫與上傳。這會先於 placement 編輯，
   因為沒貼圖就沒 placement 可編。
6. **Mode C 的 C5** — Placement 編輯器。最複雜，放最後。
7. **Mode A 的 A5（物件詳情）+ error states** — 體驗細節，收尾階段做。

## 8. 待決策事項

這些點在開發前要跟策展方或設計師確認：

- **作品平面圖長什麼樣？** A2 和 A6 需要。
- **QR 要放哪幾個位置？** 最終要幾個站點？
- **每個物件要不要配文字說明？** A5 詳情 drawer 預留了欄位。
- **Mode A 是否需要音效？** 偵測到 QR 的「叮」、物件點擊的回饋音？
- **多語言需求？** 介面文案是否需要中 / 英切換？
- **離線行為？** 展場 Wi-Fi 不穩時要怎麼 degrade？（候選：全站資源
  預先 service worker 快取）
